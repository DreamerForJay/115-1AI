# 開發過程｜趣解清明上河圖

## 1. 企劃與學習目標

這個專題想回答一個問題：一張五公尺長的畫，要怎麼在手機或電腦上看得有趣，又不失去手卷原本的讀法？我們把網站設計成一次北宋汴京散步。使用者能依序走過城郊、汴河及市區，也能跳到自己感興趣的畫面。看完後用三題小測，檢查是不是記住了原畫裡的細節。

學習目標包括知道手卷由右往左閱讀、能從圖像辨認虹橋附近的水陸交通，並能指出讓市街顯得熱鬧的具體畫面。適合在課堂中以約 3–5 分鐘示範。

## 2. 資料查核與畫面安排

1. 先查北京故宮博物院的作品頁，確認版本、作者及畫面三段的導覽順序。站點順序依手卷從右至左排列。
2. 使用 Wikimedia Commons 上的張擇端本公開影像，檢視長卷與局部。原始檔為 38,414 × 1,800 的 JPEG。先製作分段預覽找座標，再輸出全卷、縮圖、首頁虹橋特寫和六張站點局部。
3. 每站保留一段說明及一個「看一眼」提示。解說把博物院的作品描述改寫成短篇導覽，提示則引導使用者自己回到畫面辨認人物或物件。
4. 把手卷讀法、虹橋與城市街市做成三張故事卡。三道測驗題分別呼應這三個主題。

| 區域 | 導覽站點 | 用意 |
| --- | --- | --- |
| 郊外 | 城郊初見、小路行旅 | 由屋舍、小徑與人物辨認郊外景象 |
| 汴河 | 汴河船隊、虹橋過船 | 從船貨與過橋細節理解水陸交通 |
| 城內 | 穿過城門、市井百業 | 從城門轉入店鋪與行人更密集的市街 |

## 3. 網頁實作

1. **準備版面**。用 HTML 的 header、main、section、figure 和 footer 組成單頁展覽。以米白、墨綠及印章紅搭配原畫底色。桌機使用雙欄首頁與三欄故事卡，小螢幕則改為單欄。
2. **處理圖片**。以 Pillow 從單一公版來源裁切並轉成 WebP。首頁大圖優先載入，展示全卷與下方圖片可延後載入。圖片保存在專案內，瀏覽時不必另外向圖庫請求。
3. **做出展卷**。把原畫的標記像素換算成百分比，讓縮放後標記仍貼在同一個位置。以瀏覽容器的捲動位置、總寬與視窗寬，計算下方縮圖的視窗框。滑動縮圖會回寫畫卷位置。觸控使用原生水平捲動，滑鼠使用 Pointer Events 拖曳，同時保留方向鍵及 Tab 操作。
4. **串接站點與測驗**。點選原畫標記、導覽按鈕或故事卡連結，都更新同一組站點資料。測驗用當前題號、分數和作答狀態控制下一步，一題只計分一次。
5. **改善可讀性**。為主要圖片提供替代文字，按鈕保留清晰的焦點框，站點切換與答案解析提供狀態提示，並依系統減少動態效果設定停用平滑捲動。

## 4. 測試與部署

- 在 1440 px 桌機與 390 px 手機視窗檢查首頁、展卷、故事與測驗。自動測試覆蓋桌機拖曳、手機滑動、鍵盤移動、縮圖、縮放重設、故事卡跳轉、圖片載入、作答計分與重玩。
- 從專案上層透過子路徑測試，確認資產不會因 GitHub Pages 載於 `/115-1AI/` 而找不到。
- 使用 GitHub Pages 的分支發布模式，來源為 `main` 的根目錄。日後更新同一分支即可重新發布。

要重跑瀏覽器測試，先以 README 的方式啟動網站，再於另一個終端執行：

```bash
npm install --no-save --package-lock=false playwright
npx playwright install chromium
node tests/smoke.cjs
```

可設定 `SITE_URL` 指向子路徑或正式網址，也可用 `CHROMIUM_PATH` 指定已安裝的 Chromium。Playwright 只用在測試，正式網站不需要安裝套件。

## 5. 課堂展示建議

1. 先在首頁說明「這次看的不是所有版本，而是北宋張擇端本」。
2. 由右端開始展卷，從城郊直接切換到虹橋，請觀眾先找船，再看橋上哪些人正在注意船。
3. 打開城內站點，比較門樓、店鋪與街道人群，最後用三題小試收尾。

## 6. 限制與後續

畫作仍可進一步增加無障礙逐段文字稿、更多局部細節或不同版本的並排比較。目前這個版本專注於張擇端本，未加入版本對照、登入、資料庫、外部 AI API 或學習紀錄。展卷方向及畫面解說以館方標示為依據。
